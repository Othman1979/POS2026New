# POS frontend performance implementation

Authorized September 10, 2026. Work in the shared checkout on `codex/pos-frontend-audit`. Baseline: `1b1d9c5a20ea9006e6d6355a5c26d7655aa2d72b`. Follow the accompanying performance audit; preserve appearance, cart persistence, money calculations, claims, versions and print/checkout retry semantics. No deployment or integration is included.

For each correction: write behavioral regression tests, record their failure against existing code, make the smallest production change, then run the focused tests and applicable browser acceptance before the next correction.

## 1. Read correctness

- [x] Orders detail: null-safe display, real loading/error state, latest-request ownership, close/reopen and route cleanup. Keep receipt validation failures visible and prevent actions on unloaded invoices.
- [x] Held/history board: owned reads, event coalescing with a trailing refresh, reconnect recovery, explicit failure/Retry, subscribe before loading and dispose pending work/listeners safely.
- [x] Table split list: shared in-flight read plus trailing refresh; preserve final freshness, selection and transaction state across event bursts.

## 2. Unnecessary reads

- [x] Load the visible held/history tab and start independent metadata reads together. Retain read-only metadata for the visit, refresh on settings/reconnect, and reject obsolete responses. Avoid the cart's metadata loader because it also reconciles draft order types; avoid the admin cache because POS does not invalidate it globally.
- [x] Stop duplicate initial floor reads and hidden presentation-only timers while retaining recovery behavior. Split-board reconnect and overlapping loading ownership are also covered.

## 3. Measured rendering and acceptance

- [x] Measure safe derived-data reuse on large boards and catalog rendering. Keep complete board lists and existing eager operational modal loading: windowing adds variable-height/focus/full-group risks, while optional modal deferral requires new first-open/chunk recovery behavior and immediate-open watcher changes. Neither is needed for the confirmed read and rendering wins. No cart-state rewrite or new library was introduced.
- [x] Run English/Arabic desktop/mobile production-build browser cases, delayed/error/reconnect cases and repeated navigation. Compare preserved baseline evidence. Run focused selling invariant checks on guarded fixtures when appropriate.
- [x] Review all changes, build/import checks and evidence; update this document with outcomes and unresolved limits. Keep task-sized local commits. Push/PR/release/deployment require their respective authorization.

- Review correction: serialized reads need a deadline so a stalled response cannot block recovery. RED 4 HTTP-helper failures plus 2 page regressions; GREEN 46 focused tests. An opt-in 15-second read deadline covers headers and JSON body, respects caller cancellation and clears timers. Applied only to Orders details, notes metadata/lists and split-list GETs. Native browser partial-body timeout/Retry passed (`scratch/pos-frontend-deadline-fixed/results-cpu1.json`). Mutation requests retain their existing behavior.
- Catalog derivation: RED 2 failures / 2 existing passes; GREEN 22 focused catalog/category tests. Each visible product uses one store quantity calculation across repeated bindings; computed card styles retain quantity/color/selected-note invalidation. The existing store remains the authority for ID, custom-item and fractional-quantity behavior. All 698 frontend tests pass, including the replacement of an obsolete source-pattern assertion with stronger behavioral permission checks.
- Final verification review: the first 4x-CPU run reached a fixed 700 ms reconnect checkpoint with the debounce still pending. A traced rerun reached the correct 32-card snapshot by 748 ms. Replaced that arbitrary sleep-based acceptance with a bounded wait for the expected board; no production change was needed. Preserved failed-check evidence in `scratch/pos-final-reconnect-checkpoint.json` and the passing trace in `scratch/pos-frontend-reconnect-check/results-cpu4.json`.
- Final acceptance: all eight English/Arabic desktop/mobile cases passed across native and 4x CPU runs, preserving cart values and the saved note with zero Orders interaction errors. Twelve navigation cycles completed; sampled JS heap stayed between 14.07 and 14.37 MiB. Native 15-second stalled-body deadlines and Retry recovered on Orders, held orders and split checks. This is bounded fixture evidence, not proof of an indefinitely leak-free customer session or whole-machine memory use.
- Final checks: production build passed; 698 frontend tests across 113 files and 224 isolated selling tests across 7 files passed. Checkout contract and four category recovery browser cases passed.
