# Recipe ledger — Phase 3 review and fixes

Tasks 9–12 are reviewed and corrected: ingredient administration API, Ingredients workspace, product recipe editor, and the single-day ingredient report. Review began at `0d79fc08` after Phase 2. The 17 finding groups below were demonstrated by failing requests, browser interactions, or rendered output before correction. Multiple test cases for the same cause are grouped together.

## Findings and corrections

| # | Finding and reproduction before the fix | Corrected behavior and evidence |
|---|---|---|
| 1 | Weight ingredients accepted litre-based cost, par, and pack values on create/update; receipts also accepted an incompatible cost unit. | Validate every supplied unit against the ingredient measure before writing. Four API cases verify rejection and unchanged data. [API](../../backend/routes/admin/recipeLedger.js), [service](../../backend/services/RecipeLedgerService.js). |
| 2 | Negative master cost, par, and receipt cost returned success. Browser minimum attributes did not protect the API. | Server rejects negative quantities/costs; three HTTP regression cases. |
| 3 | Changing only a pack name rescaled a stored 10,000g pack into 10,000,000g. | Convert the stored base quantity into the selected input unit before applying the normal conversion. A rename followed by receiving one pack remains 10,000g. |
| 4 | Day closing omitted movements between the preceding Count and the selected day. A day with no movements also lost the carried balance. | SQL carries every applicable post-Count movement through the requested day. Count 10,000 + receipt 2,000 − waste 500 + receipt 1,000 closes at 12,500. A later inactive day retains 4,000 and below-par status. Correcting a pre-Count receipt does not change the later counted baseline. Three report cases. |
| 5 | A receipt committed between the report's balance query and movement query appeared under Received but was absent from Closing: opening 10,000, received 1,000, closing 10,000. | The [report route](../../backend/routes/admin/reports.js) owns one read-only repeatable-read transaction, including sales queries. A deterministic two-connection test injects the receipt at that boundary and verifies a coherent report. The service still never commits. |
| 6 | Ingredient controls rendered at 24px height because the page reused Inventory class names without their scoped styles. | [Ingredients](../../src/admin/pages/Ingredients.vue) now has the corresponding scoped layout, readable table, 44px controls and mobile action grid. Real browser measured 44px and verified no page overflow at 390px. The wide table scrolls within its container. |
| 7 | Editing a kg ingredient and changing display unit to g silently changed physical par/pack quantities and cost: cost 4.5, par 5, pack 10 became base values rather than preserving their meaning. | Explicit display-unit changes convert the draft values. Browser save/readback verifies cost 0.0045 per g, par 5,000g and pack 10,000g. [Form](../../src/admin/components/IngredientFormModal.vue). |
| 8 | Saving an empty Count form wrote a zero Count. | Empty quantity and pack fields produce a translated error; an explicit zero remains supported. Browser verifies no movement was written. [Movement modal](../../src/admin/components/IngredientMovementModal.vue). |
| 9 | Opening Count retry used a new client key after a committed response was lost. A receipt between attempts was then erased from expected balance by a second Count. | [Opening modal](../../src/admin/components/IngredientOpeningModal.vue) retains the key for an unchanged submitted payload. Browser lets the first POST commit, aborts its response, adds a receipt, retries, and verifies the same key and 11,000g remaining. |
| 10 | Shopping items without packs displayed no usable quantity. | Show loose quantity with its display unit; packed items retain pack count/name. Browser verifies a 1kg shortage reads `1 kg`. |
| 11 | History showed raw `10000` for a kg ingredient and Escape did not close the drawer. | [History](../../src/admin/components/IngredientHistoryDrawer.vue) shows `10 kg`, business timestamps, expected balance, date filtering, loading/error/empty states and focus handling. Additional browser control loads 52 movements across two pages, then proves a delayed old ingredient request cannot replace the newly opened ingredient. |
| 12 | Ingredient list failure silently left a blank workspace. | Visible error with Retry; list/loading/empty states are distinct. Shopping and portions failures retry their own action. Browser injects a real HTTP 500 response and verifies the error and recovery control. Inactive records can be inspected explicitly and movement controls are disabled for them. |
| 13 | Recipe Save remained enabled before the recipe GET completed, allowing the initially empty draft to clear saved lines. | [Recipe editor](../../src/admin/components/ProductRecipeEditor.vue) disables edits/save until required data loads, checks unsuccessful responses, provides Retry and ignores stale requests. Optional portions loading cannot block recipe editing. Browser holds the GET and verifies Save remains disabled, then enables after release. |
| 14 | Changing recipe quantity left the old plate cost visible as though it described the draft. | Hide saved cost/portions while the draft differs and explain that Save updates them. Use saved server price for its matching margin. Confirmed discard restores saved lines. Browser doubles a quantity and verifies the old `0.90` disappears. |
| 15 | Changing report day to one that returned 500 left old rows visible and Print enabled under the new date. | Clear old data when loading begins; unregister Print during loading/error and recheck date/readiness when the print provider actually runs. Keep the date picker available to recover. Browser verifies no old rows, disabled Print, visible error and usable date picker. [Report page](../../src/admin/pages/ReportsIngredients.vue). |
| 16 | A saved August 1–3 report period appeared in the header although the ingredient API fetched August 1 only. | Normalize this report to one business day and hide custom ranges on its tab. Its date changes persist through the parent period setter. Other report tabs retain custom periods. Browser starts with a saved three-day range and verifies the single-day header and request scope. |
| 17 | A4 and thermal reports printed raw base quantities without units. A4 also combined 500g chicken and one can into `spoiled 501`. | Both layouts convert quantities into each ingredient's display unit and print waste separately by ingredient/reason. Shared [print presentation](../../src/print/ingredientReportPresentation.js) keeps them consistent. Actual A4 SSR asserts `0.2 kg`, `11.3 kg`, `Chicken / Spoiled / 0.5 kg`, and `Pepsi / Spoiled / 1 unit`. Browser opens both layouts through the real Print menu/handshake and verifies rendered units and reasons. |

Labels for the affected inputs are accessible, new loading/error/draft copy has Arabic translations, and the Arabic mobile browser case creates an ingredient and verifies the translated blank-count error. The change keeps the existing Ingredients/Inventory visual style.

The final run includes those corrected harness assumptions.

Print tests replace `window.print` with a marker and inspect the actual rendered preview. Screenshots were inspected locally. One early SSR invocation was stopped after loading normal test setup; it ran no fixture seeding or data mutations. All database regression runs used the scratch preload.
