# Table workflow audit — 2026-09-06

This follow-up reviews the table workflow beyond the earlier connection-lifetime pass. The reviewed checkout is on `codex/system-performance-audit`, with base HEAD `f464a828b1dc8638e966fec8c27132f3a8f17eb9`. This is a route and operation inventory with concrete regression evidence, not a claim of complete branch or production coverage. Checkout authorization and the browser workflow are also being checked in the parent audit.

## Confirmed defects and changes

| Trigger | Observed before | Result after |
| --- | --- | --- |
| A waiter opens the floor plan with explicit edit, transfer, merge, override and checkout grants. | `/get_tables` selected no user ID, then loaded permissions for `undefined`; all five action flags were false. | Select the user ID before loading that user's grants. |
| An admin submits repeated new table numbers in one bulk request, including case/space variants. | The in-memory duplicate set contained existing rows only; the batch hit the unique constraint and returned 500. | Add each accepted name to the same set; insert one row. |
| A restricted waiter clears an empty joined group with `POST /table_order` and `cart: []`. | The early return detached the group before reaching table-edit authorization. | The empty-cart branch requires the existing table-edit capability and preserves the group on denial. |
| A terminal separates a joined child while its parent has unpaid split checks. | The operation raised `SPLIT_CHECKS_OPEN`, but the disjoin route changed its 409 into 500 and dropped its public code. | Preserve the domain status and code, with the existing database-error redaction. |
| Transfer, swap or merge completes. | Two extra pooled child-ID lookups preceded the broadcast query. A lookup failure returned 500 after the action had committed. | Reuse the IDs from the locked groups and call the existing best-effort broadcaster. Three follow-up reads become one. Released children remain in the captured ID set. |
| Split creation or partial payment sends a realtime floor-plan update. | The socket payload contained the original parent total and omitted `active_split_count`. The frontend merges that payload without reloading. | Both single-table and batch broadcasts return the remaining held-check total and count, matching `/get_tables`. |
| A saved product's 0.1 and 0.2 quantities are submitted as one equivalent 0.3 line for settlement. | Binary floating-point aggregation rejected the unchanged quantity with 403. | Compare integer millionths, matching the persisted six-decimal quantity scale. A change of 0.000001 is still rejected; saved rows and prices remain authoritative. |
| The held-list socket notification throws after split creation, rewrite or cancellation commits. | The request returned 500 although the mutation was durable. | Share a small best-effort notification function; preserve the committed success and still attempt the table broadcast. |

The changes introduce no schema, dependency, new permission key, deployment or machine-environment change. Table/session ownership boundaries remain the same. The local cache invalidators only assign in-memory values; this pass does not add speculative exception wrappers around them.

## Exported-operation and concurrency map

| Export | Covered responsibility |
| --- | --- |
| `saveTableOrder` | New/saved/empty/dynamic table order branches, frozen business context, stock/recipe synchronization and postcommit kitchen handoff. Evidence is the save row above. |
| `markTablePrinted` | Check-drop authorization and group-wide conditional update. |
| `processTableAction`, `joinTables`, `disjoinTables` | Transfer/swap/merge and group structure. The captured mutation set is reused for broadcasts. |
| `assertNoActiveSplitChecks` | Blocks structural changes while unpaid checks exist; exercised by transfer, save, join and disjoin guards. |
| `lockSplitCheckForMutation` | Legacy held-row lock versus progressive table/group/order then sorted sibling-held locks; missing/deleted check and competing payment/edit/discard paths. |
| `createSplitChecks`, `rewriteUnpaidSplitChecks`, `discardSplitCheck` | Progressive creation/rebalance/cancellation and retained legacy deletion; original inventory remains consumed once. |
| `lockTableSession` | Safe table/invoice identity, canonical root and consistent group, live order binding, optional money/item/bundle/snapshot lock. `tableSettlementContext.test.js` exercises joined resolution, wrong pointers, missing order, canonical saved money and invalid saved identities. |
| `reconcileSavedTableSettlement` | Rehydrate stored financial rows; reject added/removed/changed quantities, duplicated or foreign IDs and invalid fee shape. The new real save/checkout regression covers six-decimal aggregation. |
| `broadcastTableUpdate`, `broadcastTableUpdates` | No-op for missing IO/IDs, ID deduplication, single/batch current snapshots and best-effort failures. New tests cover remaining split balance/count for both shapes. |

Real concurrent database tests include save versus checkout; same-table settlement versus settlement; split payment versus unpaid-group edit; two split discards; and parallel numbering/register/table settlement. Deterministic lock-order assertions also cover joined-group saves and transfers. They do not enumerate every possible scheduling order or establish a production contention benchmark.

The existing policy intentionally remains visible for review: split creation enforces owner/override and printed-table rules, while rewrite/cancel are exposed to staff with `pos.split_checks` on the global split board. No narrower owner-only rewrite/cancel policy was introduced without an established requirement. Join still has no durable `table_join` audit row; changing audit policy is outside these fixes.
