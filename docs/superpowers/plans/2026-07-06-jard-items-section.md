# جرد (Audit Report) — Items Section Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a new "Items" (الأصناف) section to the جرد audit report (Z / X / periodical), listing every product sold in the selected range, ordered by tax-inclusive total, rendered on both the browser preview and the thermal spooler, placed directly under the existing Categories (المجموعات) section.

**Architecture:** The جرد report is a single JSON payload built once by `backend/services/auditReportBuilder.js` and rendered in **two** places: the browser preview (`src/print/PrintReceiptApp.vue`) and the physical thermal spooler (`pos-spooler-printer/server.js`). Both read the same payload. We add one new data function `getItems()` to the builder (an exact mirror of the existing `getCategories()`, grouped by item name instead of category), expose it on the payload as `payload.items`, then render that array in both renderers. Because the builder is range-driven, the same code automatically serves single-business-date reports (Z/X) **and** periodical (date-range) reports — no branching needed.

**Tech Stack:** Node.js (CommonJS) backend, MySQL (mysql2), Vitest for tests, Vue 3 SFC for the browser preview, plain Node HTML-string templating for the spooler.

2. **Payload builder (backend):** `backend/services/auditReportBuilder.js` → `buildAuditReportPayload(executor, options)`. 3. **Renderer A — browser preview:** `src/print/PrintReceiptApp.vue`, the `v-if="printType === 'audit_report'"` block (starts line ~226). The Categories section header `المجموعات` is at line ~295. This is **Task 2**.
4. **Renderer B — thermal spooler:** `pos-spooler-printer/server.js`, the `if (print_type === 'audit_report')` block (starts line ~651). The Categories section (`المجموعات`) is at line ~726. This is **Task 3**.

**Why `getItems` is a near-copy of `getCategories`:** they must reconcile. If you sum every item's `gross_revenue` you should get (approximately) the same total as summing every category's `gross_revenue`, because both aggregate the same `order_items` rows with the same tax / order-discount / refund / void handling. The ONLY differences are the grouped column (`item_name` vs `category_name`), the removal of the unused `categories` join, and a secondary sort tiebreaker. Do not "improve" the formula — copy it exactly.

**`payload_hash`:** the builder hashes the entire payload (minus the hash field) for tamper-evidence. Because `items` is a new payload field, newly generated reports will hash differently than before — this is expected and correct. Reprints re-render a stored payload, so there is no mismatch. No test asserts a fixed hash value (only a `/^[a-f0-9]{64}$/` shape check), so nothing breaks. You do NOT need to change `hashPayload`.

async function getItems(executor, range) {
    const [rows] = await executor.query(`
        SELECT
            COALESCE(oi.item_name, p.name, 'Unknown') AS item_name,
            SUM(GREATEST(0, oi.quantity - COALESCE(rfi.rq, 0))) AS qty_sold,
            SUM(GREATEST(0,
                ${lineSubtotalAfterOrderDiscount('oi', 'o')}
                + COALESCE(oi.tax_amount, 0)
                - COALESCE(rfi.rs, 0)
                - COALESCE(rfi.rt, 0)
            )) AS gross_revenue
        FROM order_items oi
        JOIN orders o ON oi.invoice_id = o.invoice_id
        LEFT JOIN products p ON oi.product_id = p.id
        LEFT JOIN (
            SELECT ri.order_item_id, SUM(ri.quantity) AS rq, SUM(ri.line_subtotal) AS rs, SUM(ri.line_tax) AS rt
            FROM refund_items ri
            JOIN refunds r ON r.id = ri.refund_id
            WHERE r.kind = 'refund'
            GROUP BY ri.order_item_id
        ) rfi ON rfi.order_item_id = oi.id
        WHERE ${paidOrderTimeSql('o')} >= ? AND ${paidOrderTimeSql('o')} < ?
          AND o.payment_method NOT IN ('unpaid_table', 'voided')
        GROUP BY COALESCE(oi.item_name, p.name, 'Unknown')
        ORDER BY gross_revenue DESC, item_name ASC
    `, [range.start, range.end]);

    return rows.map(row => ({
        item_name: row.item_name,
        qty_sold: toQty(row.qty_sold),
        gross_revenue: toMoney(row.gross_revenue),
    }));
}
